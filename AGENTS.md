# AGENTS.md — PasteDownloadApp

## Project Overview

Static marketing website + client-side web application at **pastedownloadapp.com**. The app lets users paste images from clipboard or download from URLs. All processing happens client-side (no uploads). Built with Astro, deployed to Cloudflare Pages.

## Tech Stack

| Layer | Technology |
|---|---|
| Meta-framework | **Astro v6.4.4** (`@astrojs/cloudflare` adapter, `@astrojs/sitemap`) |
| CSS | **Tailwind CSS v4.3.0** via `@tailwindcss/vite` plugin |
| Language | TypeScript (Astro frontmatter), vanilla JS (client scripts) |
| Package manager | npm (`>=22.12.0`) |
| Deployment | Cloudflare Pages via wrangler |

## Commands

| Command | Action |
|---|---|
| `npm run dev` | Start dev server at `localhost:4321` |
| `npm run build` | Build to `./dist/` |
| `npm run preview` | Preview production build |
| `npm run deploy` | Build + deploy to Cloudflare Pages |

**No linting, formatting, or testing tooling exists.** The only validation is TypeScript strict mode (from `astro/tsconfigs/strict`).

## Coding Conventions

### General
- 2-space indentation everywhere
- Single quotes in JS/TS
- Semicolons required
- No trailing commas in source code

### Imports
- Relative imports with explicit file extensions (`.astro`)
```astro
import Header from '../components/Header.astro';
import Layout from '../layouts/Layout.astro';
import '../styles/global.css';
```

### Components
- **Single-file Astro components** only — no React, Vue, Svelte, or other framework islands
- Frontmatter (`---`), template HTML, optional `<style>`, optional `<script>` at the bottom
- Props defined via `export interface Props`, destructured from `Astro.props`
```astro
---
export interface Props {
  title: string;
  description: string;
}
const { title, description } = Astro.props;
---
```
- Client scripts: `<script>` at bottom of component (Astro auto-bundles them)
- Inline scripts (`<script is:inline>`) only for critical path items (GA, structured data, theme toggle)

### CSS
- **Tailwind CSS v4** with `@tailwindcss/vite` (no PostCSS config, no `tailwind.config.*`)
- Custom design tokens in `src/styles/global.css` using `@theme` directive
- Custom `@custom-variant dark` using `.dark` class strategy
- CSS variables from theme: `var(--color-ink)`, `var(--color-canvas-soft)`, etc.
- Per-component `<style>` only for effects that utilities can't express (e.g., hero mesh gradient)
- Use Tailwind utility classes inline; custom class names in kebab-case only when necessary

### Client-Side JS
- **Vanilla JS only** — no frameworks
- DOM queries: `document.getElementById()`, `document.querySelector()`
- Event listeners: `addEventListener`
- Core APIs: Clipboard API (`navigator.clipboard.read()`), Canvas API (`canvas.toBlob()`), drag-and-drop
- Utility functions (formatFileSize, downloadBlob, etc.) defined inline per component

### File & Naming Conventions
- **Components**: PascalCase (`PasteZone.astro`, `HowItWorks.astro`)
- **Pages**: lowercase (`index.astro`, `privacy.astro`, `blog/index.astro`)
- **Layouts**: PascalCase (`Layout.astro`, `ContentLayout.astro`)
- **Prop names**: camelCase
- **CSS classes**: Tailwind utilities inline; custom classes kebab-case
- **HTML IDs**: camelCase (`pasteDropZone`, `themeToggle`, `autoDownload`)

### SEO & Meta
- Each page has: `<title>`, `<meta description>`, `<link rel="canonical">`, OG tags, Twitter card
- JSON-LD structured data on every page (Organization, WebSite, WebApplication, FAQPage, etc.)
- Sitemap auto-generated by `@astrojs/sitemap`

### Accessibility
- Skip-to-content link on homepage
- `aria-hidden="true"` on decorative icons
- `aria-label` on interactive elements
- `role="status"` + `aria-live="polite"` on dynamic status elements
- `focus-visible:ring-2 focus-visible:ring-link focus-visible:outline-none` on interactive elements
- `.sr-only` for screen-reader-only content

## Design System

See `DESIGN.md` for the complete design system. Key highlights:

- **Colors**: 30+ named tokens (ink `#171717`, canvas `#ffffff`, canvas-soft `#fafafa`, hairline `#ebebeb`, link `#0070f3`, etc.)
- **Typography**: Inter (geometric sans) + JetBrains Mono. Aggressive negative tracking on display sizes. Sentence-case headlines, often period-terminated.
- **Shadows**: Stacked shadows (multiple small offsets + inset hairline), never single heavy drops
- **Border radius**: Marketing CTAs = `rounded-full` (pill), nav buttons = `rounded-md`, cards = `rounded-xl`
- **Component tokens**: nav-bar, buttons (primary/secondary at 2 scales), cards, inputs, pricing cards, badges, hero-band, etc.
- **Dark mode**: `.dark` class strategy, invert canvas/ink/hairline

## Do's

- Use Tailwind utility classes from the `@theme` tokens (`bg-canvas`, `text-ink`, `border-hairline`, `text-link`, etc.)
- Set every headline with tight tracking (`tracking-tight` or `tracking-tighter`)
- Use semantic HTML and ARIA attributes for accessibility
- Apply `focus-visible` ring styles on all interactive elements
- Load Google Fonts (Inter + JetBrains Mono) in layouts
- Use `overflow-hidden` for card border-radius clipping

## Don'ts

- Don't add framework components (React, Vue, Svelte) — use vanilla Astro only
- Don't add PostCSS or Tailwind config files — Tailwind v4 uses `@import "tailwindcss"` in CSS
- Don't add environment variables or `.env` files — the project has none
- Don't add server-side logic or API routes — this is a fully static site
- Don't add inline styles unless unavoidable — use Tailwind utilities instead
- Don't add new CSS files unless necessary — put styles in `global.css` or component `<style>` blocks
- Don't use `import` in client-side `<script>` blocks (Astro bundles `module` type scripts by default)
- Don't add emojis unless the user explicitly asks for them
- Don't add comments to code unless necessary for clarity
- Don't modify `opencode.json`, `skills-lock.json`, or `.agents/` unless specifically asked
- Don't use em dashes anywhere in the content
